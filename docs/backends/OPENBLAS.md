# Backend: OpenBLAS

The reference backend — the working implementation of
[`../KERNELS.md`](../KERNELS.md) and the model for future backends
(oneMATH, CLBlast, …). Fork: OpenBLAS pinned at `e016600` (v0.3.34 line),
carried as a submodule of this repo and kept at the pristine upstream
commit. **All work ships as one patch**: `physics_kernels.patch` at the
repo root. The submodule pointer is never advanced.

## Build notes

The canonical clone/patch/build/install/verify sequence is the
[README quickstart](../../README.md#quickstart-openblas-backend)
(utest suites: 220 + 2765 checks; the `_ext` suite holds the cblas tests
of the new kernels). Backend-specific knobs: threading builds add
`-DSMP_SERVER -DUSE_THREAD -DMAX_CPU_NUMBER=4
-DBUILD_{SINGLE,DOUBLE,COMPLEX,COMPLEX16}=1` (validated with forced
`OPENBLAS_NUM_THREADS=4`, bitwise T1-vs-T4 on every threaded entry);
`cmake` is the only working build path in this checkout (no
`configure`/Make prebuild). The `benchmark/` suite links **only** the
installed tree (`pkgs/openblas/{include/openblas,lib}`) — referencing the
source+build trees duplicates headers and macros.

Install-directory quirk: the installed `cblas.h` is a **configure-time
copy** (`build/generated/cblas.h`, generated by a textual
`s/common/openblas_config/` transform of the source header). After
editing `cblas.h`, re-run configure (or regenerate that file with the same
transform) before `cmake --install`, or the prefix silently keeps the old
prototypes.

## Patch workflow

The fork's working tree carries the change; nothing is ever committed to
the fork itself.

```sh
# regenerate
cd openblas && git add -A && git diff --cached > ../physics_kernels.patch && git reset -q
# verify on a scratch index (no full-tree copies, ever)
rm -f /tmp/x.idx
GIT_INDEX_FILE=/tmp/x.idx git read-tree e016600
GIT_INDEX_FILE=/tmp/x.idx git apply --cached ../physics_kernels.patch
GIT_INDEX_FILE=/tmp/x.idx git apply -R --cached --check ../physics_kernels.patch
rm -f /tmp/x.idx
```

Checks before committing the patch: zero `GIT binary patch` hits, no
`v3blas.mod` (or other artifacts) staged, whitespace warnings tolerated.
Large files (`v3blas.f90`) are handled fine; keep the diff textual.

## Kernel file pattern

Per op `<stem>` (example: `1xypa`), following exactly how `axpy`/`geadd`
are done:

| file | contents |
|---|---|
| `kernel/generic/<stem>.c` | real kernels (s, d share the file — precision comes from `-DFLOAT` etc.) |
| `kernel/generic/z<stem>.c` | complex kernels (c, z share; `FLOAT` = component type) |
| `interface/<stem>.c` | one file → both the F77 symbol (`d3cross_`) and `cblas_d3cross`; compiled twice, once per flavor |
| `interface/z<stem>.c` | complex counterpart |
| `utest/test_<stem>.c` | unit test, calls the F77 entries |
| `utest/test_extensions/test_{s,d,c,z}<stem>.c` | cblas tests, one per precision |

Kernel ABI (the level-1 threaded calling convention):

```c
int CNAME(BLASLONG n, BLASLONG dummy0, BLASLONG dummy1, /* scalars */
          FLOAT *x1, BLASLONG incx1, ..., FLOAT *out, BLASLONG inout,
          FLOAT *dummy, BLASLONG dummy2)
```

`dummy0/dummy1` (front) and `dummy/dummy2` (back) are ABI padding.
Internally the kernel takes **scalars before the dummies** (the calling
convention the SMP marshaller passes) even where the *public* order is
name-ordered — the interface layer reorders. Complex: `FLOAT` is the
component type, arrays are interleaved re/im, the interface doubles
strides, complex scalars arrive as `FLOAT ar, FLOAT ai`. Macro names
follow the stem uppercased (`XYPA_K` — C identifiers can't start with a
digit).

## Wiring checklist (per kernel)

- `kernel/Makefile.L1`: `S/DBLASOBJS += <stem>_k` (per precision) + compile rules
- `kernel/CMakeLists.txt` (float/double/complex/zcomplex loops next to `geadd`) + `cmake/kernel.cmake` (`SetDefaultL1` fallbacks) + `PhysicsKernelOptimize(<generated wrappers>)`
- `common_level1.h` prototypes; `common_{s,d,c,z}.h` dispatch macros (both the non-DYNAMIC **and** DYNAMIC blocks); `common_macro.h` alias blocks (all four precisions); `common_param.h` `gotoblas_t` field; `kernel/setparam-ref.c` initializer; `common_interface.h` F77 prototypes
- `interface/Makefile`: objects into `S/DBLAS1OBJS` (×cblas `C*` variants) + rules
- `interface/CMakeLists.txt`: `<stem>.c` into `BLAS1_MANGLED_SOURCES` — list the base name **once**; the complex `z`-prefix entry is auto-generated
- `cblas.h`: `cblas_<p><stem>` declarations (mind the generated-copy quirk above)
- `exports/gensymbol`: the 4 F77 names in per-precision lists + `cblas_*` in the cblas lists (unlisted symbols are invisible in the shared lib)
- `utest/Makefile` (`OBJS`, `OBJS_EXT`) and `utest/CMakeLists.txt`

## Threading — `blas_physics_thread`

The OpenBLAS way: interface decides, driver dispatches. **Do not reuse
`blas_level1_thread`** — it only advances the A and B pointers between
chunks (C stays at base: every thread scribbles the same output — the bug
that bit `1xypa` first) and mis-multiplies complex strides. Instead
`driver/others/blas_physics_thread.c` provides

```c
blas_physics_thread(shape, mode, n, scalars, ptrs, incs, nptr, kfunc, nthreads)
```

which slices `n` like the L1 helper but strides **every** pointer with its
own increment, then runs the kernel through the normal `exec_blas()`
worker pool. Interfaces carry a small `#ifdef SMP` block: a shape id
(`PHYS_3HAD … PHYS_LAP7` in `common_level1.h`), scalar/pointer slots in
`phys_slice_t`, and the serial gate
`any inc == 0 || n <= PHYS_MT_MIN (10000) ? 1 : num_cpu_avail(1)`.
Threaded: the 3-vector output ops + `lap5/lap7` × `s d c z`;
reduction-output ops and `1xypa` stay serial (pinned summation order).
Slot counts: `3crosscross` needs 12 pointers, `3crossxy_crossxz` 15 (its
third group is the INPUT `w` — mis-sloting it corrupts the next op's
data); only `3crossscal` has a complex scalar (re/im in slots 0–1). The
driver entry compiles only under `if (USE_THREAD)` in CMake.
`PHYS_MT_MIN` wants retuning on real silicon from a crossover curve
(open item, [`../TODO.md`](../TODO.md)).

## Optimization

- Stock generic kernels build with **no optimization flags**; the CMake
  option `PHYS_KERNELS_O3` (default ON, warned at configure time either
  way) compiles only the physics kernels with `-O3` — on ARMv6 that gets
  the VFPv2 `vmla` fusion; verified in the shipped objects. All physics
  kernels opt in via `PhysicsKernelOptimize()` in their
  `kernel/CMakeLists.txt` entry. Never `-Ofast`.
- Unrolled `inc==1` fast path + strided fallback (the `axpy` idiom) took
  `d1xypa` from 2.1× to ~1.0–1.2× of the hand-tuned asm `daxpy` at
  n=100000; small-n (~1000) stays ~2× off (latency regime, asm wins) —
  not chased in generic C.
- L1 threading of bandwidth-bound streaming kernels is questionable
  anyway; upstream itself disables L1 threading below n≈10000.

## Front-end files

`v3blas.h` (C11 `_Generic`, one `V3BLAS_DEFINE` macro × 4 precisions),
`v3blas.hpp` (inline overloads; both headers C- and C++-clean — include
exactly one), `v3blas.f90` (F2003 `iso_c_binding` module, generated-style
but ordinary source: 76 wrappers over 76 bind(C) interfaces; 16
field-form ops + 3 one-vector ops × 4 precisions; `gfortran -std=f2008
-Wall` clean). All three live at the OpenBLAS root and install next to
`cblas.h`. The Fortran module represents a 3-vector as one field `u(n, 3)`
— column-major, so each column `u(:, c)` *is* one contiguous component
array (the SoA blocks the kernels read); no strides, no `n` in field-form
calls, runtime `size(u,2)==3` guard (the square `(3,3)` shape is the
accepted blind spot); non-contiguous actuals (slices, transposes) route
through a hidden gfortran copy — correct but pointless, pass whole
`(n,3)` arrays. Raw F77 triplets stay one `call d3cross_` away.

## Gotchas earned here

- `common_level1.h` once lost its tail to a bad sed insertion (restore =
  diff against upstream; verify `#if` balance and a purely-additive diff).
- `interface/CMakeLists.txt` carried a stale duplicate wiring block from a
  scripted insertion (cleaned 2026-10-11) — always inspect, not just
  append, when scripting build-file edits.
- C macro parameters don't thread through nested file-level macros —
  per-precision exec functions open with `typedef float FT;` instead.
- The standalone f90 module compile drops `v3blas.mod` into the fork root
  — gitignored; keep it that way or the patch grows a binary blob.
- utest takes a substring filter as a positional argument —
  `./openblas_utest_ext 1xypa` — which makes single-op iteration fast on
  the Pi (an unmatched filter just runs 0 tests, exit 0: check the count).
